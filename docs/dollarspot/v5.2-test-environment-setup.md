# DollarSpot Sentinel v5.2 - Setup ambiente test

## Obiettivo

Creare un ambiente v5.2 TEST parallelo alla produzione corrente, senza disturbare i superintendent dei 7 campi in test.

## File Apps Script da copiare nel progetto TEST

```text
Setup_v5_2.gs
DollarSpot_Sentinel_v5_2_TEST.gs
MeteoCache_v5_2.gs
MeteoProvider_v5_2.gs
```

## Procedura consigliata

### 1. Duplicare spreadsheet

Duplicare lo spreadsheet oggi usato in produzione.

Nome suggerito:

```text
DollarSpot Sentinel v5.2 TEST
```

### 2. Creare progetto Apps Script TEST

Nel file duplicato:

1. Aprire Estensioni -> Apps Script.
2. Creare o sostituire i file `.gs` con i moduli v5.2.
3. Non modificare lo script di produzione attuale.

### 3. Eseguire setup

Nel progetto Apps Script TEST eseguire:

```javascript
setupDollarSpotV52TestEnvironment()
```

La funzione:

- crea i fogli mancanti;
- aggiunge header minimi;
- aggiunge colonne sicurezza in `Campi`;
- genera `campoId`;
- genera `tokenCampo`;
- imposta `attivo = true`;
- valida l'ambiente.

Nota: il setup v5.2 accetta gli header gia presenti nel tuo foglio, ad esempio `Nome Campo`, `Latitudine`, `Longitudine`, `Profilo`, `Feltro 1-9`. Non serve rinominarli a mano in formato tecnico.

### 4. Verificare ambiente

Eseguire:

```javascript
validateDollarSpotV52Environment()
```

Non proseguire se segnala:

- coordinate mancanti;
- token mancanti;
- header mancanti;
- fogli mancanti.

### 5. Aggiornare meteo cache

Eseguire manualmente:

```javascript
aggiornaMeteoCacheTuttiCampi()
```

Controllare che `MeteoCache` contenga righe per ogni campo attivo.

### 6. Creare trigger meteo

Trigger consigliato:

```text
aggiornaMeteoCacheTuttiCampi
ogni giorno
ore 06:00-06:30
```

### 7. Pubblicare Web App TEST

Deploy:

```text
Execute as: Me
Who has access: Anyone
```

Usare solo URL TEST.

### 8. Preparare link frontend test

Formato consigliato:

```text
superintendent_v5_2_TEST.html?campo=Green%201&tokenCampo=<TOKEN_CAMPO>
```

Nel frontend:

- `fieldName` deve essere readonly;
- `tokenCampo` viene letto dall'URL;
- il campo effettivo viene comunque deciso dal backend.

## Primo test manuale

1. Aprire link test con token di un campo.
2. Salvare annotazione.
3. Controllare `Registro`.
4. Controllare `Audit`.
5. Provare token errato.
6. Controllare `Errori`.
7. Salvare rullatura.
8. Salvare azoto con data futura e verificare rifiuto.

## Modalita ombra

Quando i salvataggi funzionano:

- lasciare produzione invariata;
- usare v5.2 TEST solo per calcoli interni;
- inviare email solo all'agronomo;
- confrontare output per alcuni cicli.

## Cosa non fare

- Non cambiare URL Web App dei superintendent.
- Non sostituire il codice produzione.
- Non cancellare fogli produzione.
- Non migrare tutti i campi insieme.

## Prossimo step dopo il setup

Integrare il sorgente completo v5.1/v5.2:

```text
apps-script/DollarSpot_Sentinel_v5_1_PRODUZIONE.gs
web/superintendent_v9.html
```

Poi creare:

```text
apps-script/DollarSpot_Sentinel_v5_2_FULL_TEST.gs
web/superintendent_v5_2_TEST.html
```
