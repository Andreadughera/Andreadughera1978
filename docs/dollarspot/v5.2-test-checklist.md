# DollarSpot Sentinel v5.2 - Checklist test

## Scopo

Validare la v5.2 prima di darla ai superintendent, riducendo al minimo il rischio di disservizio sui campi attualmente in test.

## 1. Test di sicurezza

- [ ] `doPost` rifiuta richieste senza `tokenCampo`.
- [ ] `doPost` rifiuta token non esistenti.
- [ ] `doPost` rifiuta token di campo non attivo.
- [ ] Il backend ricava il campo dal token.
- [ ] Cambiare `fieldName` nel browser non permette di scrivere su un altro campo.
- [ ] Token hardcoded rimossi dal codice sorgente.
- [ ] Chiavi API spostate in `PropertiesService`.

## 2. Test salvataggio registro

### Azoto

- [ ] Salvataggio con NPK valido.
- [ ] Rifiuto NPK non valido.
- [ ] Rifiuto kg/ha vuoto o negativo.
- [ ] Rifiuto data futura.
- [ ] Scrittura corretta in `Registro`.
- [ ] Calcolo N disponibile coerente.

### Ferro

- [ ] Salvataggio FeSO4.
- [ ] Rifiuto data futura.
- [ ] Moltiplicatore residuo coerente per 0-7, 7-14, 14-21, >21 giorni.

### Fungicida / biologico

- [ ] Salvataggio prodotto ammesso.
- [ ] Rifiuto prodotto non ammesso.
- [ ] Rifiuto data futura.
- [ ] Moltiplicatore residuo coerente con curva prodotto.

### Rullatura

- [ ] `rullatura` accettata da `doPost`.
- [ ] Scrittura corretta in `Registro`.
- [ ] Moltiplicatore `0.85` per i primi 3 giorni.
- [ ] Ritorno a `1.00` dopo 3 giorni.

### Annotazione

- [ ] Salvataggio nota testuale.
- [ ] Rifiuto nota vuota.
- [ ] Scrittura corretta con campo derivato dal token.

## 3. Test meteo

- [ ] WeatherAPI risponde correttamente.
- [ ] Open-Meteo fallback funziona se WeatherAPI fallisce.
- [ ] Cache meteo viene usata entro la finestra prevista.
- [ ] Ultimo dato valido viene usato se tutte le API falliscono.
- [ ] Errore meteo viene scritto in `Errori`.
- [ ] Soil temperature viene valorizzata anche quando la fonte principale e WeatherAPI.
- [ ] Dati null non falsano le medie.

## 4. Test modello rischio

- [ ] Rischio finale sempre tra 0 e 100.
- [ ] Finestra stagionale disattiva il rischio fuori stagione.
- [ ] Cultivar `alta_resistenza` riduce rischio.
- [ ] Cultivar `alta_suscett` aumenta rischio.
- [ ] Temperatura suolo sotto 8 C porta moltiplicatore 0.
- [ ] Soglia climatica adattiva resta tra 12 e 28.
- [ ] Pressione cumulativa applica bonus massimo 60%.
- [ ] Verde/giallo/rosso coerenti con soglia adattiva.

## 5. Test email

- [ ] Email superintendent non inviata fuori stagione.
- [ ] Email superintendent inviata solo se previsto dalla policy alert.
- [ ] Riepilogo agronomo sempre generato in produzione.
- [ ] In modalita test, email solo all'agronomo.
- [ ] Bottone feedback apre pagina conferma.
- [ ] Il primo click non registra evento reale.
- [ ] Secondo click registra evento reale.
- [ ] Eventi ammessi:
  - [ ] `macchie_viste`
  - [ ] `nessuna_macchia`
  - [ ] `trattato`
  - [ ] `situazione_dubbia`

## 6. Test frontend

- [ ] Campo visualizzato readonly o non autoritativo.
- [ ] Token letto da URL o configurazione sicura.
- [ ] Date future bloccate nel browser.
- [ ] Se il salvataggio non e confermato, la UI non mostra "sincronizzato".
- [ ] Log locale continua a funzionare.
- [ ] Registro locale non crea duplicati evidenti.
- [ ] Analisi locale marcata come stima se non viene dal backend.

## 7. Test modalita ombra

Per ogni campo test:

- [ ] v5.1 continua a inviare alert reali.
- [ ] v5.2 scrive solo su fogli test.
- [ ] v5.2 invia email solo all'agronomo.
- [ ] Rischio v5.1 e v5.2 confrontati.
- [ ] Differenze superiori a una soglia definita sono spiegate.

## 8. Test pilota

- [ ] Un solo campo riceve link v5.2.
- [ ] Vecchio link resta disponibile.
- [ ] Primo salvataggio verificato manualmente.
- [ ] Prima email verificata manualmente.
- [ ] Nessun dato scritto su campo sbagliato.
- [ ] Feedback del superintendent raccolto.

## 9. Criteri stop

Non procedere alla migrazione se accade uno di questi casi:

- Scrittura su campo sbagliato.
- Errore non gestito in `doPost`.
- API meteo falliscono senza fallback.
- Email inviata con dati incoerenti.
- Rischio v5.2 molto diverso da v5.1 senza spiegazione.
- UI mostra "sincronizzato" quando il backend non ha salvato.

## 10. Criteri go-live

La v5.2 puo essere distribuita a tutti quando:

- Checklist sicurezza completata.
- Registro validato su tutti i tipi.
- Meteo fallback validato.
- Pilota completato senza errori critici.
- Rollback provato.
- Documentazione aggiornata.
