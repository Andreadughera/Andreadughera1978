# DollarSpot Sentinel v5.1 - Mappa integrazione verso v5.2

## Scopo

Questo documento mappa il sorgente Apps Script v5.1 condiviso e indica dove integrare i moduli v5.2 gia presenti nel repository.

Il sorgente v5.1 non viene committato integralmente in chiaro perche contiene valori sensibili hardcoded, tra cui:

- `TOKEN_SEGRETO`
- `WEATHERAPI_KEY`
- URL/asset embedded

Prima di versionare il sorgente completo, questi valori vanno spostati in `PropertiesService`.

## Funzioni critiche nel sorgente v5.1

### 1. `CONFIG`

Stato attuale:

```javascript
TOKEN_SEGRETO: "..."
```

Problema:

- Token globale hardcoded.
- Non c'e token per campo.

v5.2:

- Usare `PropertiesService` per segreti globali.
- Usare `tokenCampo` per i superintendent.
- Ricavare `campo` dal token.

### 2. `doPost(e)`

Stato attuale:

```javascript
var data = JSON.parse(raw);
var tipo = data.tipo || 'unknown';

if (tipo === 'azoto' || tipo === 'ferro' || tipo === 'fungo' || tipo === 'annotazione') {
  salvaRegistro(data);
}
```

Problemi:

- Nessun controllo token.
- `campo` arriva dal browser.
- Non supporta `rullatura`.
- Nessuna validazione payload.

v5.2:

- Sostituire con il `doPost` presente in `DollarSpot_Sentinel_v5_2_TEST.gs`.

### 3. `doGet(e)`

Stato attuale:

- Controlla solo `CONFIG.TOKEN_SEGRETO`.
- Registra `evento_reale` al primo click.

Problema:

- Un client email/antispam puo aprire il link e registrare evento falso.

v5.2:

- Primo click apre pagina di conferma.
- Secondo click registra feedback.
- Eventi consigliati:
  - `macchie_viste`
  - `nessuna_macchia`
  - `trattato`
  - `situazione_dubbia`

### 4. `salvaRegistro(data)`

Stato attuale:

- Scrive colonne A:K.
- Non include `campoId`.
- Non include `requestId`.
- Non gestisce bene `rullatura`.

v5.2:

- Usare `salvaRegistro_` del layer test.
- Aggiungere colonne:
  - `CampoId`
  - `RequestId`

### 5. Funzioni registro: date future

Funzioni interessate:

- `getNDisponibile`
- `getFerroMult`
- `getFungoMult`
- `getRullaturaMult`
- `getZolfoMult`

Problema:

- Se una data futura viene inserita per errore, il moltiplicatore puo risultare attivo.

Patch minima:

```javascript
if (giorni < 0) continue;
```

Per azoto:

```javascript
if (settimane < 0) continue;
```

### 6. `fetchMeteo(lat, lon)`

Stato attuale:

- WeatherAPI primaria.
- Open-Meteo fallback.
- Cache in `PropertiesService`.

Problemi:

- Soil temperature spesso non disponibile quando WeatherAPI funziona.
- Cache properties puo diventare pesante.
- Se entrambe le API falliscono, il campo viene saltato.

v5.2:

Sostituire:

```javascript
var meteo = fetchMeteo(lat, lon);
```

con:

```javascript
var meteo = fetchMeteoV52({
  campoId: campoId,
  nomeCampo: nomeCampo,
  lat: lat,
  lon: lon
});
Logger.log("  " + getMeteoQualityLabelV52(meteo));
```

### 7. `calcolaRischioStorico`

Stato attuale:

- Calcola temperatura suolo solo da `meteo.archH.soil_temperature_0cm`.

Problema:

- Con WeatherAPI il dato e sempre `null`.

v5.2:

Sostituire il recupero temperatura suolo con:

```javascript
var tSuolo = getTSuoloGiornoV52(meteo, meteo.archH, d);
```

### 8. `computeRisk`

Stato attuale:

```javascript
var lwd = stimaLWD(hourly,dateStr);
```

v5.2:

Permettere uso cache:

```javascript
var lwd = getLwdOreV52(meteo, hourly, dateStr);
```

Nota: richiede di passare `meteo` a `computeRisk`, oppure creare una variante `computeRiskV52`.

### 9. `calcolaForecast`

Stato attuale:

```javascript
meteo.foreD.time.slice(1,4)
```

Rischio:

- A seconda della fonte, il primo giorno forecast puo essere gia escluso.

v5.2:

- Normalizzare in `MeteoProvider_v5_2.gs`.
- Usare `foreD.time` come restituito dal provider.

### 10. `fetchProfiloClimatico`

Stato attuale:

```javascript
var cacheKey = 'profilo_' + nomeCampo.replace(/\s/g,'_');
```

Problemi:

- Collisione se due campi hanno stesso nome.
- Medie con `null` trattati come zero.

Patch minima:

```javascript
var cacheKey = 'profilo_' + campoId + '_' + lat + '_' + lon;
```

e filtrare solo valori numerici validi.

## Ordine di integrazione consigliato

1. Copiare sorgente v5.1 in `apps-script/DollarSpot_Sentinel_v5_1_PRODUZIONE.gs` sanitizzato.
2. Creare `DollarSpot_Sentinel_v5_2_FULL_TEST.gs`.
3. Integrare `Setup_v5_2.gs`.
4. Integrare `DollarSpot_Sentinel_v5_2_TEST.gs` per `doPost`/sicurezza.
5. Integrare `MeteoCache_v5_2.gs`.
6. Integrare `MeteoProvider_v5_2.gs`.
7. Sostituire `fetchMeteo` con `fetchMeteoV52`.
8. Eseguire modalita ombra.

## Nota importante

Non applicare queste modifiche direttamente alla Web App attuale dei 7 campi. Usare solo ambiente v5.2 TEST.
