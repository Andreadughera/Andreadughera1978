# DollarSpot Sentinel v5.2 - MeteoCache

## Obiettivo

Usare Google Sheets come cache/fonte meteo controllabile, riducendo disservizi causati da API non disponibili, dati mancanti o risposte lente.

Lo script Claviere condiviso e una buona base per un singolo campo. In v5.2 va generalizzato per piu campi e integrato nel flusso di alert.

## Problemi dello script attuale

Lo script attuale:

- usa coordinate hardcoded di Golf Claviere;
- scrive su un foglio `Meteo` dedicato;
- pulisce tutto il contenuto a ogni aggiornamento;
- non gestisce piu campi;
- non salva `campoId`;
- non distingue chiaramente qualita dato/cache/fallback;
- non contiene temperatura suolo;
- usa CSV con parsing semplice.

Va bene come dashboard meteo visuale, ma per il motore v5.2 serve un formato dati piu stabile.

## Schema consigliato `MeteoCache`

Una riga per campo e data.

| Colonna | Campo | Note |
| --- | --- | --- |
| A | `Data` | Data meteo |
| B | `CampoId` | ID stabile del campo |
| C | `NomeCampo` | Nome leggibile |
| D | `Lat` | Coordinate usate |
| E | `Lon` | Coordinate usate |
| F | `Tipo` | `storico`, `oggi`, `forecast` |
| G | `Fonte` | `open-meteo`, `weatherapi`, `manuale`, `cache` |
| H | `TMin` | C |
| I | `TMax` | C |
| J | `TMedia` | C |
| K | `UmiditaMedia` | % |
| L | `Pioggia` | mm |
| M | `VentoMax` | km/h |
| N | `ET0` | mm |
| O | `TempSuolo` | C, se disponibile |
| P | `LWD` | ore, se calcolata |
| Q | `AggiornatoIl` | timestamp |
| R | `QualitaDato` | `live`, `cache_oggi`, `cache_recente`, `manuale`, `errore` |
| S | `Note` | dettagli/fallback |

## Strategia di lettura meteo v5.2

Ordine consigliato:

1. Prova API live.
2. Se API live funziona, aggiorna `MeteoCache`.
3. Se API live fallisce, leggi `MeteoCache` per campo/data.
4. Se cache di oggi non esiste, usa cache recente.
5. Se cache recente manca o e troppo vecchia, non inviare alert automatico e registra errore.

## Qualita dato

Usare `QualitaDato` per rendere trasparente il livello di affidabilita:

- `live`: dato appena scaricato da API.
- `cache_oggi`: dato preso da cache aggiornata oggi.
- `cache_recente`: dato preso da cache non odierna ma ancora accettabile.
- `manuale`: dato inserito/corretto manualmente.
- `errore`: dato incompleto o non utilizzabile.

Nelle email si puo mostrare:

> Dati meteo: live, aggiornati 11/05/2026 09:00

oppure:

> Dati meteo: cache recente, ultimo aggiornamento 10/05/2026 09:00

## Regole di sicurezza operativa

- Non cancellare lo storico completo della cache.
- Aggiornare le righe per chiave `CampoId + Data`, non appendere duplicati.
- Conservare almeno 30 giorni storico e 7 giorni forecast.
- Non usare dati con `QualitaDato = errore` per inviare alert automatici.
- Se si usano dati cache, scriverlo in audit/log.

## Collegamento con v5.2

Il modulo `apps-script/MeteoCache_v5_2.gs` implementa:

- aggiornamento multi-campo da Open-Meteo;
- scrittura upsert su `MeteoCache`;
- lettura fallback da cache;
- normalizzazione dei dati;
- qualita dato.

## Evoluzione futura

Quando il sistema diventa commerciale:

- mantenere `MeteoCache` come fallback visibile;
- usare API live nel backend per calcolo ufficiale;
- mostrare stato meteo in dashboard;
- monitorare errori API in `Errori`;
- aggiungere alert all'agronomo se un campo non aggiorna meteo.
